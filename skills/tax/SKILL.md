# 세무 검토 (tax)

한국 세법 질문을 받아 **TaxDoctor 세법 MCP**(서버 이름 `korea-tax-law`,
`https://mcp.taxdoctorai.com/mcp`)로 법령·판례·결정례·예규·별표·부칙·조세조약을 검색하고,
근거 기반 검토의견을 작성한다.

| MCP | 무엇 | 언제 쓰나 |
|---|---|---|
| **korea-tax-law** (주) | 세법 그래프 DB(읽기 전용). 국세·지방세 현행 법·령·칙과 지난 시점 판, 부칙 적용례·경과조치, 판례·조세심판원·국세청 불복 결정례, 국세청·법제처·행안부 해석례, 별표·서식, 시행예정 개정, 조세조약이 **본문까지** 들어 있고 위임·인용 관계로 이어져 있다. 세법과 따로 표시된 **비세법 참조 법령**(민법·주택법·민간임대주택법·도시정비법·노동·사회보험 법령 등)과 조정대상지역 지정 이력도 있다 | 세법 안의 일은 전부 여기서. 조문·위임 추적·판례·해석례·별표·과거 시점 조문·부칙·조약·인용 검증, 그리고 수록된 비세법 전제 조문 |

이 문서와 `references/`에 적은 도구(`search_tax`, `get_article` …)는 모두 korea-tax-law 도구다.
이 서버에 없는 법령(참조 법령 목록에도 없는 세법 밖 법령·조례)과 수록 범위(조문마다 다르고 대략
2015~2016년 이후) 앞 시점의 조문은 조회하지 못한 것으로 답변에 밝히고, 국가법령정보센터(law.go.kr)
확인을 안내한다.

사용자 입력: $ARGUMENTS

## 0. 준비

- **경로 확인**: 이 SKILL.md와 같은 폴더의 `references/`에 단계별 지침이 있다.
  아래에서 "references/…"는 항상 이 스킬 폴더 기준 **절대경로로 풀어서** 사용한다
  (서브에이전트에 넘길 때 특히).
- **오늘 날짜 확인**: 질문 속 "작년", "10년 전 증여", "지금 팔면" 같은 상대 날짜는 오늘
  날짜로 실제 연월을 셈해야 개정 전후·기간 요건이 갈린다. 오늘 날짜를 확인해 두고,
  hard 모드에서는 [1]·[4] 단계 입력 첫 줄에 `오늘 날짜: YYYY-MM-DD`로 넘긴다.
- **MCP 확인**: 도구 접두사는 설치 방식마다 다르다 — 직접 등록하면
  `mcp__korea-tax-law__…`, 플러그인으로 설치하면 `mcp__plugin_<플러그인 이름>_korea-tax-law__…`,
  claude.ai 커넥터로 붙였으면 `mcp__claude_ai_<커넥터 이름>__…`. **도구 이름 끝**
  (`search_tax`, `get_article`, `verify_citations`)으로 찾는다.
  - korea-tax-law 도구가 없으면 검색을 진행하지 말고 MCP 설정이 필요하다고 안내한다
    (README 참조). **자체 지식만으로 세법 답변을 만들지 않는다.**
  - korea-tax-law에 없는 세법 밖 법령이 전제인 대목은 "해당 법령은 확인하지 못했다"고
    답변에 명시하고 국가법령정보센터(law.go.kr) 확인을 권한다. 기억으로 조문을 채우지 않는다.

## 1. 모드 결정

| 모드 | 언제 | 무엇 |
|---|---|---|
| **easy** (기본) | 단순 조회·일반 설명·빠른 확인 | 검색 + 답변 작성 + 인용 검증. 2~5분 |
| **hard** | 사용자가 명시(`hard`, "정밀 검토", "딥하게")했거나, 복합 쟁점·고액 리스크·해석 대립·과거 과세기간 판단이 걸린 질문 | 4단계 전체 파이프라인 (분석 → 검색 → 검증 → 답변) + 인용 검증. 10분 이상 |

- 인자 첫 단어가 `easy`/`hard`면 그 모드로 확정하고 나머지를 질문으로 본다.
- 지정이 없으면 easy로 시작하되, 질문이 hard 기준에 해당하면 **easy로 답한 뒤
  말미에** "쟁점이 복합적이니 `hard` 모드 정밀 검토를 권합니다"를 붙인다.
- 질문이 세무가 아니라 이 스킬·서버 자체(사용법·연결 방법·수록 범위)를 묻는 것이면
  검색 없이 README에 적힌 범위에서 답한다. 세무 질문이 섞여 있으면 세무 부분을 검토한다.

## 2. easy 모드

메인 컨텍스트에서 직접 수행한다. 별도 분석·검증 단계 없이 **검색 → 답변 → 인용 검증**.

1. **질문 읽기**: 검색 전에 `references/query-analysis.md`의 §3-1(사실관계·방향)과
   §4(검색 의도 작성 기준)를 머릿속 점검표로 쓴다 — 사용자가 준 사실과 "누가 누구에게"
   방향을 고정하고, 기한 질문의 기산일 조문, 조특법 감면·공제의 공통 제한 조문,
   비과세 제외분의 계산 조문, 불리한 가설을 푸는 특례 조문을 검색 대상에 넣는다.
2. **검색**: 아래 라우팅대로 검색한다. easy 모드는 응답이 가벼운 **개별 도구**를 쓴다
   (`search_tax`는 조문에 이어진 판례·해석례를 `detail: "list"` 목록으로 훑을 때만 쓴다).
   호출은 8~10회 안팎에서 끝낸다.

   | 찾는 것 | 도구 |
   |---|---|
   | 세법 조문 (법령 약칭 + 조번호를 앎) | `search_articles`에 그대로 — "조특법 29조의8", "소득령 155", "부가세법 60조"는 그 조문을 바로 준다. 원문 전체는 `get_article` |
   | 세법 조문 (번호를 모름) | `search_articles`에 실무 용어("접대비", "경정청구 기한", "간이과세 기준금액") — AI 관련도 순위로 후보가 온다. 순위는 검증된 인용이 아니니 **제목·본문을 보고 고른 뒤** `get_article`로 확인. `law_name`으로 법령 한정, `limit` 최대 20 |
   | 조문 원문 | `get_article(law_name, article_number)` — 위임 하위법령 목록·검증된 인용 판례·해석례 목록·시행예정 개정 표시까지 함께 온다. 약칭(조특법·상증법·국기법)도 받는다 |
   | 법률 조문과 짝이 되는 시행령·시행규칙 | `get_article_tiers` — 3단 본문을 한 번에. 시행령 조문을 넣어도 위아래를 찾는다 |
   | 세율표·기준금액·한도 (별표 위임) | `get_annex` (번호 모르면 `search_annexes`). 6,000자씩 오고 긴 표는 `offset`으로 이어 읽는다 |
   | 판례·조세심판원·국세청 불복 결정례 | `search_cases` — 단일 핵심 키워드. 사건번호를 넣으면 그 사건을 맨 앞에, 법원 판결은 주문·원심·환송 후 판결까지 붙여 준다 |
   | 국세청·법제처·행안부 해석례 | `search_interpretations` — 쟁점 문장을 그대로 넣어도 되고 문서번호도 받는다 |
   | 조문에 이어진 판례·해석례·부칙 훑기 | `search_tax` — `{"search_intents": {"law": ["소득세법 제97조의2"]}, "detail": "list", "limit": 100}`. 목록에서 고른 것만 `get_evidence`로 읽는다 |
   | 지난 사업연도·과세기간·거래일에 시행 중이던 조문 | `get_article(law_name, article_number, as_of="2023-12-31")` — 그날의 판과 판 목록이 온다. 응답 첫 줄이 `[NOT_COVERED:before_data]`이거나 '확인 불가'면 **현행 본문으로 대신하지 않는다** |
   | 언제부터 적용되나 (적용례·경과조치) | `get_amendments(law_name, article_number, period_start, period_end)` — 취득·증여·양도일 같은 사건 날짜를 넣으면 그 기간에 걸리는 부칙 조항만 골라 준다 |
   | 조문이 언제 바뀌었나 | `get_article_history` — 버전별 시행 구간. 무엇이 바뀌었는지는 `get_article(as_of)`로 판을 견준다 |
   | 내년 이후 과세기간·"앞으로 바뀌나" | 쟁점 조문은 `get_article`의 시행예정 표시, 법령 전체는 `list_upcoming(law_name)`. 개정 내용 전문을 읽지 못했으면 "○○○○년 ○월 시행 개정이 예정돼 있어 그 시점 조문 확인이 필요하다"까지만 쓴다 |
   | 조세조약 | `list_treaties` → `search_treaties` → `get_treaty_article`. 제한세율은 반드시 `get_treaty_article`에서 읽는다 — 본문은 협약 원문이고, 뒤에 붙는 "이 조문을 개정한 부속문서" 발췌가 바뀐 세율이다 |
   | 세법 밖 전제 조문 (민법·주택법·민간임대주택법·도시정비법·근로기준법·4대보험 법령 등) | `get_reference_article(law_name, article_number, as_of)` / `search_reference_articles`. 응답에 "세법이 아님"이 붙는다 — 세법상 결론은 세법 조문으로 따로 확인 |
   | 참조 법령 목록에도 없는 법령 (공정거래법 등) | 이 서버로는 조회할 수 없다. 그 전제가 걸린 대목은 "확인하지 못했다"고 밝히고 국가법령정보센터(law.go.kr) 확인을 안내 |
   | 조정대상지역·투기과열지구·투기지역 지정 여부 | `get_regulated_area_history(region, as_of)` — 세법 아님. 중과·거주요건 효과는 세법 조문으로 |
   | 수록 법령인지 확인 | `list_laws` (세법 목록과 비세법 참조 법령 목록을 함께 준다) |

   - **조문 번호를 기억으로 찍지 않는다.** 번호가 확실하지 않으면 `search_articles`로
     먼저 찾는다. 그래도 없으면 `search_interpretations` 결과의 `[관련법령]`에서 조문
     번호를 얻어 `get_article`로 확인한다. 세율·한도·기한 같은 수치는 반드시
     `get_article`·`get_annex` 원문에서 읽는다.
   - 검색 확장 순서: 직접 적용 조문 → 위임 시행령 → (불명확할 때만) 해석례 → (판단
     기준이 판례로 형성된 쟁점만) 판례. 앞에서 충분하면 뒤는 검색하지 않는다.
     조문이 다른 조문을 끌어와 단서·예외를 정하면, 답변에서 설명할 것만 열어 본다.
   - 키워드 검색 히트와 AI 관련도 순위는 "그 말이 본문에 있다/관련 있어 보인다"는
     뜻일 뿐이다. 요지만 보고 인용하지 말고, 결론을 기대는 문서는 본문을 확인한다.
     해석례는 회신까지 읽는다.
   - 조문이 기준을 하위 법령·고시에 맡겼는데 응답에 "위임 법령 미수록"이 붙으면 그
     기준값은 이번 검토에서 확인하지 못한 것이다 — 조문에 보이는 하한·범위로 값을
     정하지 않는다.
   - 비거주자·외국법인 쟁점은 국내법 조문과 해당국 조약 조문을 **함께** 확인한다.
   - 서로 독립인 검색은 병렬 호출.
3. **답변**: `references/answer-generation.md`를 Read하고 그 지침대로 작성한다.
   - easy 모드는 검증 단계가 없으므로 지침 §4의 easy 모드 주의 의무(단서·예외·
     적용제외 함께 제시, 확신도를 한 칸 올려 쓰지 않음)를 반드시 지킨다.
4. **인용 검증**: 작성한 답변(본문 + 인용 근거 목록, 면책 문구 제외)을
   `verify_citations`에 넣는다. 결과 처리는 §4.

## 3. hard 모드

taxdoctorai.com 검토 파이프라인의 4단계를 **단계별 서브에이전트**로 실행한다.
오케스트레이터(메인 컨텍스트)는 아래 실행 규칙만 따르고, 법률 판단을 직접 하지 않는다.

```
사용자 질문
  → [1] Query Analysis (서브에이전트)
      ├─ clarification_needed.required = true
      │    → 재질문 내용을 사용자에게 그대로 전달하고 종료 (검색 시작 금지)
      └─ false
           → [2] Source Search (서브에이전트)
           → [3] FactCheck (서브에이전트)  ※ lookup_only=true면 생략
               ├─ supplement_search 있음 → [2]를 해당 키워드로만 1회 재실행 → [3] 재실행
               └─ 없음
           → [4] Answer Generation (서브에이전트)
           → [5] 인용 검증 (오케스트레이터가 verify_citations 1회)
  → 답변을 그대로 사용자에게 전달
```

**실행 규칙**:
1. 오케스트레이터는 세법상 쟁점이나 검색 대상을 자체 판단하지 않는다 — 각 단계
   산출물을 **가공 없이** 다음 단계에 전달만 한다.
2. Query Analysis가 재질문이 필요하다고 하면 검색을 시작하지 않는다. 사용자가
   답하면 원래 질문과 합쳐 [1]부터 다시 실행한다 (두 번째 라운드는 재질문 없이
   본 검토로 진행). 사용자 답은 `[사용자의 추가 답변 — 확인된 사실]` 머리를 붙여 넘긴다.
3. 보충 검색은 FactCheck의 `supplement_search`에 명시된 키워드만, **최대 1회**.
4. `lookup_only=true`(단순 조회형)면 [3]을 건너뛰고, [4]에 "검증 단계가 생략되었으니
   단서·예외 규정을 반드시 함께 제시하라"는 주의를 덧붙인다.
5. 같은 대화에서 이어지는 질문(후속·정정·반박)이면 [1]에 직전 문답을 함께 넘기되,
   사용자의 새 메시지는 `[사용자의 새 메시지]` 머리를 붙여 **자르지 않고** 넘긴다.

**서브에이전트 호출 방법** — 각 단계는 general-purpose 에이전트로 실행한다.
프롬프트 형식 (경로는 절대경로로):

- **[1] Query Analysis**:
  > `<references 절대경로>/query-analysis.md`를 Read하고 그 지침을 정확히 따라
  > 아래 세무 질문을 분석하라. 출력은 지침 §3의 JSON만 반환한다.
  > 오늘 날짜: <YYYY-MM-DD>
  > 사용자 질문: <질문 원문 그대로 — 요약·재작성 금지>

  > `coverage_gaps`에 적는다. 출력은 지침 §4의 JSON만 반환한다.

- **[3] FactCheck**:

합치거나 건너뛰지 않는다.

## 4. 인용 검증과 답변 전달

답변(본문 + 인용 근거 목록)을 `verify_citations(text=답변)`에 한 번 넣어, 적힌
조문·판례·문서번호가 DB에 실제로 있는지 확인한다(한 번에 기본 15건, `max_citations`
최대 30). 이 도구는 **그 번호의 조문·문서가 있는지**만 본다 — 내용이 맞는지, 항·호
번호가 맞는지는 보지 않는다. 결과는 `articles[]`·`documents[]`의 `status`로 읽는다.

| 결과 | 뜻 | 처리 |
|---|---|---|
| `found` (+ `title_check: match`) | 그 번호의 조문·문서가 있다 | 그대로 둔다 |
| `found_reference` | 비세법 참조 법령(민법 등)에 그 조문이 있다 — 세법 조문이 아니다 | 그대로 둔다. 그 조문으로 세법상 결론을 낸 곳이 있으면 확인 메모 |
| `not_found` | 지어낸 번호이거나 DB 미수록(`reason`·`current_range`가 붙으면 그 법령에 없는 조번호) | 아래 "확인 메모"에 적는다 |
| `title_check: mismatch` | 조문은 있는데 괄호 안 제목이 현행 제목과 다르다 | 확인 메모 |
| `current_number` · `moved_hint` | 옛 조문 번호를 썼거나, 그 번호의 조문이 최근 다른 번호로 옮겨졌다 | 확인 메모 (현행 번호 병기) |
| `renumbered` | 해석례의 예전 번호와 지금 국세청 번호가 다른 같은 문서 | 그대로 두되 지금 번호(`current_number`)를 병기 |
| `number_conflict` | 해석례 목록 번호와 원문 번호가 달라 그 문서인지 확정하지 못했다 | 확인 메모 |
| 판례 `history` | 원심·상고심·파기환송 후 판결 | 인용한 판결이 뒤에서 뒤집혔으면 확인 메모 |
| `status: unchecked` · `unresolved_articles` | 검사하지 못했다 (법령명 생략 표기, 부칙 조문 등) | 통과로 치지 않는다. 검색 단계에서 원문을 확인한 것(`get_reference_article`로 본 참조 법령, `get_amendments`로 본 부칙)이면 그대로 두고, 아니면 확인 메모 |

- **easy 모드**: 답변을 쓴 것이 자신이므로, 걸린 인용은 `get_article` 등으로 다시
  확인해 바로잡거나 뺀 뒤 전달한다. 다시 확인해도 못 찾으면 확인 메모로 남긴다.
- **hard 모드**: 답변 본문은 고치지 않는다. 걸린 인용이 있으면 확인 메모만 덧붙인다.

확인 메모는 두 모드 모두 면책 문구 바로 앞에 아래 꼴로 붙인다. 걸린 것이 없으면
아무것도 붙이지 않는다. (답변 지침의 "내부 작업 노출 금지"는 답변 본문에 대한 것이고,
이 메모는 스킬이 따로 붙이는 검증 결과다.)

```
**인용 확인 메모**
- <답변에 적힌 인용 그대로> — <검증 결과 한 줄: DB에서 확인되지 않음 / 현행 제목은 ○○ / 현행 번호는 제○조>
```

그 밖에는 파이프라인(또는 easy 모드)이 만든 답변을 **그대로** 사용자에게 전달한다.

- 요약하지 않는다. 다듬지 않는다. 문단을 재배열하지 않는다.
- 근거를 추가하거나 결론을 보태지 않는다. 스스로 아는 세법 지식으로 거들지 않는다.
- 답변이 이상하거나 근거가 빈약해 보이면, 고치지 말고 그 사실을 사용자에게 말한다.
- 말미에 항상 붙인다(답변 지침의 상담 권고 문구와 별개로, 스킬이 붙이는 면책이다): *"본 스킬의 답변은 AI가 공개 법령정보를 검색해 작성한 참고
  의견이며, 세무대리인의 검토를 대체하지 않습니다. 실제 신고·처분 대응 전 반드시
  회계사 또는 세무사와 상담하세요. 답변의 정확성·완전성은 보장되지 않으며, 이를
  근거로 한 의사결정의 책임은 사용자에게 있습니다."*

## 5. 공통 답변 원칙

- 모든 법적 판단에 조문번호·판례번호·문서번호 인용 필수
- **검색으로 확인한 근거만 인용** — 자체 지식의 조문번호를 검색 없이 쓰지 않는다
- 조문은 **현행 시행본** 기준이다. 과거 과세기간은 그 시점 조문을 확인한 경우에만
  판단하고, 확인하지 못했으면 현행 조문으로 대신하지 않는다. 다만 시점 판 "확인 불가"는
  그 규정이 **적용되지 않는다는 뜻이 아니다** — 적용 여부는 판단을 보류한다
- 확정적 단언 금지 → 근거 강도에 맞춘 조건부 표현
- 반대 근거 병기 의무
- 사실관계 미확인 시 "확인 필요" 명시 (단 방향성 있는 결론과 함께)
- 사용자가 준 사실·가정은 확인된 사실로 쓰고, 반박만으로 결론을 뒤집지 않는다

## 6. 실패 시

| 증상 | 대응 |
|---|---|
| korea-tax-law 도구가 안 보임 | MCP 설정 안내 (README 참조). 자체 지식으로 답하지 않는다 |
| 호출 한도 안내 (`retry_after_seconds` 또는 "잠시 뒤 다시") | 안내된 만큼 기다렸다 다시 부른다. 무시하고 계속 부르면 한동안 호출이 막힌다 |
| MCP 호출 연속 실패 | 2~3회 재시도 후 사용자에게 서버 상태를 알리고 중단 |
| 응답 첫 줄이 `[NOT_FOUND]` | 법령명·조번호가 수록 범위에 없다. `list_laws`로 수록 여부를 확인하고, 세법 밖 법령이면 `get_reference_article`·`search_reference_articles`로. 거기에도 없으면 "확인하지 못했다"고 명시 |
| 응답 첫 줄이 `[NOT_COVERED:…]` | 그 시점 판이 수록 범위 밖이다. 현행으로 대신하지 말고 "확인 불가"로 답변에 명시하고 그 시점 조문은 국가법령정보센터(law.go.kr)에서 확인하도록 안내 |
| 검색 0건 | 키워드 일반화 1회 재시도 → `list_laws`로 수록 법령인지 확인 → 그래도 없으면 답변에 그 한계를 명시 |
| 응답이 너무 큼 (`search_tax`) | 여러 건은 `detail: "list"`로 목록만 받고, 원문은 `limit` 1~3으로 읽는다 (`references/source-search.md` §2-A) |

실패를 자체 지식으로 메우지 않는다. 실패는 실패로 보고한다.
